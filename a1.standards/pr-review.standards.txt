Pull Request and Review Standards
=================================
Version: 1.0
Date: 2026-03-17

1. Pull Request Requirements
   1.1. Every change must go through a pull request.
   1.2. PR title must reference the task ID (e.g., "260317.task-01: Setup repos").
   1.3. PR description must include:
        - Summary of changes (what and why).
        - Link to the task folder or report.
        - Test results or test plan.

2. Review Process
   2.1. Every PR must be reviewed before merging.
   2.2. Reviews test the PR against the standards in a1.standards/.
   2.3. A PR must not be merged unless the review confirms the PR
        passes all applicable standards.

3. Review Checklist
   3.1. Language standards compliance (language.standards.txt).
   3.2. File format standards compliance (file-format.standards.txt).
   3.3. Task management standards compliance (task-management.standards.txt).
   3.4. Tests exist and pass for all workflows and code.
   3.5. No vague referrants in any documentation or code comments.

4. Commit Message Standards
   4.1. Commit messages must be a single line. No multi-line messages.
   4.2. No Co-Authored-By lines or trailers.
   4.3. Format: type: description
   4.4. Valid prefixes:
        - feat:     New feature.
        - fix:      Bug fix.
        - doc:      Documentation changes.
        - refactor: Code restructuring without behavior change.
        - test:     Adding or updating tests.
        - chore:    Maintenance, config, dependencies.
        - style:    Formatting, whitespace, no logic change.
   4.5. Example: "feat: add user authentication endpoint"
   4.6. The description must be lowercase and concise.

5. Testing Requirements
   4.1. Every workflow must have tests that verify the workflow
        produces the expected output.
   4.2. Every code change must have tests that cover the changed
        behavior.
   4.3. Tests must pass before the PR can be merged.
   4.4. Test files are stored alongside the code or workflow
        they test.
